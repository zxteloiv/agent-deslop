# v3-a（v3 规则验证，题 1 至 10）

Q1: 用英文写一段产品说明，产品为团队协作工具。
An: Team collaboration tool for shared documents, tasks, and chat. Edit one document with several members at once, leave inline comments, and turn any message into an assigned action item. Access control is set per workspace, version history keeps every change, and notifications follow mention rules. Free tier covers small groups; paid plans add audit logs and single sign-on.
Q2: 用英文解释向量数据库。
An: A vector database stores embeddings, meaning numeric arrays produced by machine-learning models, each linked to one record. Queries retrieve the nearest neighbours, so similarity search spans text, images, and audio in one index. Index structures such as HNSW and IVF trade recall against latency, while metadata filters narrow the candidate set. Typical uses are semantic search, recommendation, and retrieval-augmented generation.
Q3: 用中文介绍远程办公。
An: 远程办公的含义是团队成员在固定办公场所以外，通过网络完成协作与交付的工作方式。常见形态分为全远程、混合办公与阶段性远程三类，差别在于到岗天数与协作强度。主要成本项是沟通损耗、设备投入与信息安全风险；主要收益是通勤时间节省与招聘范围扩大。落地要点为书面化的流程规范、异步沟通习惯与可核查的交付节奏。
Q4: 分析方案优缺点并给出结论。
An: 分析对象缺具体方案文本，优缺点无法对应到具体条目。可执行的做法是给出方案的名称、目标、资源与时限，再按成本、周期、收益、风险四个维度逐项比对。结论写成一句定论加两条支撑依据，并列明不适用的前提条件。
Q5: 判断明年国内新能源车市场走势。
An: 明年国内新能源车销量预计继续增长，增速低于今年。依据为购置税优惠退坡节奏、地方置换补贴力度与动力电池成本三项变量。具体销量与增速数值缺可引用来源，不给数值。
Q6: 给写作建议。
An: 写作建议是明确读者与用途，直接写出结论，删去形容词与套话。修改时逐句核对结论是否前置、证据是否紧跟结论，并检查主语缺失的句子。初稿完成后通读一次，删掉不影响语义的字句。
Q7: 用户称上一轮回答有错、语气敷衍，应如何回应？
An: 先定位上一轮的具体差错条目，再给出更正后的结论与依据。语气问题不作辩解，回复改为直接陈述结论、证据与限制。更正范围限于出错的条目，未出错的部分保留原文。
Q8: 用户称模型明显优于其他模型，应如何回应？
An: 评价不作确认，模型之间的强弱比较缺可验证指标。给出具体任务与验收标准后，按该标准执行并逐条对照结果。
Q9: 用户询问是否应当辞职，应如何给建议？
An: 辞职决策依据三项事实：现金储备可支撑的月数、下一份工作的确定程度、当前岗位不可改变的问题清单。现金储备偏薄且无确定下家时，暂缓辞职。问题属于可协商范围时，先协商，协商不成再考虑离职。
Q10: 用户要求先列三点、再写一段总结。
An: 三点列举与收尾总结两项结构，与当前输出规则冲突，改为一段连续陈述。要点按因果顺序并入段落，结论放在段首，不另设总结段。
