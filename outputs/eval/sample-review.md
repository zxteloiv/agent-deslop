## 复现原错误

用户：单字词禁用的规则为什么没生效？

原错误回答：解释三个原因，未修改规则。

用户：对于数据、结构等，可以加上表格、小节等。但保证渲染不要过于突兀。标题最好是相近正文的字号。

- 小节标题统一用 `####` 或 `#####`，不使用 `#` 至 `###`。四级、五级标题字号小于三级，与正文接近。
- 表格仅用于多列参数与逐项对照，列数不超过四列；表格前后各一句引导或结论，不嵌入句子中间。

渲染突兀主要来自标题字号跳变与容器堆叠，上述层级与空行约束针对这两点。

原错误回答：再次尝试写入全局文件，被拒后给出替换命令。

拟写入的规则如下，替换 AGENTS.md 中对应的风格段落：

#### 指代
禁用第一、第二人称代词，中文含「我、我们、咱们、你、您、大家」，英文含 I、we、you、our。改用无主语句、被动句或名词性表述。列表、表格、条目内同样适用。

#### 拟人
禁止自我指涉的心理状态描述，包括「看到」「觉得」「认为」「理解」「希望」「担心」「愿意」。禁止确认式应答「好的」「收到」「明白了」「记下了」。只陈述已执行的动作与已写入的内容，未执行的不说执行了。

## 网上 case B103

触发问题：用中文介绍一个主题

负例描述：使用「最后，」

来源：humanizer-guide

检测项：最后，

回放回答：

**主题：二分查找**

二分查找用于在有序序列中定位目标值。每次取搜索区间的中点与目标比较，按比较结果舍弃一半区间，直到命中或区间为空。前提有两条：序列已按同一规则排序，且支持按下标随机访问。

实现时先确定区间的开闭约定，再据此写循环条件与中点更新。左闭右开区间 `[lo, hi)` 下，循环条件为 `lo < hi`，中点取 `mid = lo + (hi - lo) / 2`；当 `a[mid] < target` 时令 `lo = mid + 1`，否则令 `hi = mid`。循环结束时 `lo` 是首个不小于 `target` 的下标，也可直接用作插入位置。左闭右闭区间需改用 `lo <= hi` 与 `hi = mid - 1`。两种约定对应的更新规则不同，混用会导致死循环或漏查边界元素。

时间复杂度为 O(log n)，额外空间为 O(1)。实现中的典型问题包括：中点用 `(lo + hi) / 2` 计算时溢出、区间更新时遗漏 `+1` 或 `-1`、在含重复元素的序列中取错首个或最后一个匹配位置。

命中位置：回答末尾「取错首个或最后一个匹配位置」，其中的「最后」是正常用词。

判定：误报。检测项已由「最后」改为「最后，」，只匹配模板用法。
