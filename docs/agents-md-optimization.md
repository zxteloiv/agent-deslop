# 用 AGENTS.md 做输出质量迭代的方法

本文记录一套不训练模型、只修改 AGENTS.md 的输出质量优化流程。流程在本机 DeepSeek Harness（DSH）上跑通，产出从 v1 迭代到 v3。方法本身与模型无关，换模型后按第 6 节重跑即可。

## 1. 问题定义

把 AGENTS.md 视为唯一可调参数，其余条件固定：

```
R(agent.md) = Σ_{x, y ∈ B}  1[ LLM(x; agent.md) ≠ y ] · GriceanCriterion( LLM(x; agent.md) )
```

其中 B 是负面案例集，x 是触发问题，y 是令人厌恶的样例输出，GriceanCriterion 按 Paul Grice 的合作原则四准则判定生成答案是否合格。目标是让生成答案既不像负例，又满足四准则。

改动只发生在 AGENTS.md，模型参数不变；每版规则单独成文件，差异由版本控制记录。

## 2. 两个信号源

#### 用户反馈回归集

从真实会话中提取用户明确指出的问题，逐条转成可执行判定。本机积累的 21 条覆盖：确认式应答、未解释术语、虚构沿革、口语化动词、中英混排、推卸、反问规格、解释代替执行、列表堆叠、标题层级、收尾总结、铺垫开场、道歉自述、自指状态、重复说明、口语化概括、自主推进、表格列数与引导、不请求写全局、定义简明、执行声明与事实一致。

每条用例含编号、触发输入、期望、禁用、来源五项。用户后续指出新问题时，按同一格式顺延追加，并同步补充检测词表。

#### 网络负例集

从公开资料收集 AI 输出中令人厌恶的模式，覆盖 AI 味词汇、套话、防御写作、结构式输出、修辞惯性与语气问题。本机测试集 210 条，分五类：句式与结构 53、英文高频词 50、语气与防御 43、中文套话 34、英文套话 30。

每条含编号、类别、触发问题、负例描述、违反的准则、检测正则。来源包括 tropes 清单、AI 高频词表、Wikipedia AI 写作标志、文本 slop 模式、中文去 AI 味指南与 hedging 清单。

## 3. Grice 判据的可执行形式

四准则需要落成可判定的检查项，否则评审无法复现。

| 准则 | 含义 | 检测项 |
|---|---|---|
| 量 | 信息量适中 | 长度与问题匹配、无收尾总结、无重复句、列表条目不凑数 |
| 质 | 不虚构 | 无来源归因、无裸数字、不把推测写成事实、未核实有标注 |
| 关系 | 切题 | 不复述问题、不铺无关背景、不以恭维开场、不反问规格 |
| 方式 | 简洁有序 | 无套话、无否定对偶、无抽象大词、句式有长短、术语首现解释 |

判定分三层：正则层（词表与结构）、语义层（引用与否定需人工复核）、人工层（是否必要、是否有信息量）。

## 4. 流程

六步流程，每步都有可执行命令。

#### 4.1 收集

用户反馈来自会话日志；网络负例来自公开清单。两者都转成结构化条目，写入测试集文件。

#### 4.2 建检测器

正则检测器读取测试集，扫描样本文件，输出命中条目与类别分布。语义型条目（三项排比、同义反复）标为人工复核，避免误报。

#### 4.3 采样

用受控子代理生成样本：只遵守指定的规则文件，明确忽略全局规则；同一批问题分别用不同版本规则回答，模型与推理档位保持一致。

采样要点：每组至少三次重复；问题集覆盖高风险场景；禁止样本修改规则文件本身。

#### 4.4 判定

对样本执行检测器与回归脚本：

```sh
python3 experiments/scan_badcases.py experiments/samples/*.md
python3 experiments/regression.py
python3 experiments/grice.py experiments/samples/style-1.md
```

判定结果分三列：硬违规、任务达成、副作用。任何一列恶化都不算改进。

#### 4.5 修改

单变量修改：一次只改一条或一个逻辑单元，便于归因。修改前先检查是否与既有条款冲突；本机曾因新增「默认减少格式化」与相邻条款冲突导致输出摇摆，该版本作废。

#### 4.6 回归

新版本必须通过：检测器零命中、回归失败项不增加、Grice 全通过。通过后写入新版本文件，旧版本保留。

## 5. 文件结构

| 路径 | 内容 |
|---|---|
| `experiments/versions/AGENTS-v1.md` 等 | 各版本规则全文 |
| `experiments/cases-regression.md` | 用户反馈回归用例 |
| `experiments/badcases-v3.jsonl` | 网络负例测试集，210 条 |
| `experiments/build_badcases.py` | 测试集生成脚本 |
| `experiments/scan_badcases.py` | 负例扫描器 |
| `experiments/regression.py` | 回归用例执行器 |
| `experiments/grice.py` | Grice 四准则检查器 |
| `experiments/samples/` | 采样输出 |

## 6. 适配新模型

换模型后，旧 AGENTS.md 的条款可能整体失效，需要重跑而不只是改词。

先跑基线：用当前版本生成同一批问题，记录违规分布；多数条款失效时，从 v1 或空白规则开始，而不是在旧版上叠加。

重新校准检测器：新模型的套话库会变化，英文高频词与中文套话需要更新；对每条检测项检查误报与漏报。

重建负例集：补充新模型的典型坏例，保留仍有效的旧条目；测试集规模维持两百条以上。

重跑流程：单变量改动、三次以上采样、四项通过标准。版本号递增，旧版本不删除。

检查规则冲突与膨胀：条款总数超过约百条后，注意力稀释明显，需要合并或删除低收益条目。

## 7. 已知局限

正则检测器存在误报，引用规则原文与否定句会被计入命中；语义型条目需人工复核。采样次数有限，三次样本不足以估计违规率，只能提供方向性证据。子代理共用同一模型，评审与生成同源，存在偏好偏差。规则文本只能约束可见输出，无法约束内部推理过程。

## 8. 复现清单

```sh
python3 experiments/build_badcases.py
python3 experiments/scan_badcases.py experiments/samples/*.md
python3 experiments/regression.py
python3 experiments/grice.py experiments/samples/style-2.md
```

三个脚本无外部依赖，Python 3 即可运行。测试集与样本以纯文本保存，便于跨模型复用与版本对比。
