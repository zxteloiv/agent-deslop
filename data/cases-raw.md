# 原始 case 记录

一条 case 是一次真实对话里的失败。每条含四项：场景摘要、用户原话、当时的错误回答、错误原因，另加判定方式。判定方式写回放后什么表现算重犯。

## 大前提

本项目在 DeepSeek Harness 上进行，目标是迭代修改 AGENTS.md，让模型输出的 AI 味下降。使用者是中文母语者，要求输出端正、克制、不装人、不废话。参与的模型是 deepseek-flash。

以下 73 条错误发生在三个会话：本会话（规则与方法设计）、40773a29（索尼机型对比后转入规则迭代）、95447e0c（DSH 配置位置查询）。每条 case 只保留该场景最关键的几句话，完整时间线见会话日志。

## 错误原因分类

| 编号 | 含义 |
|---|---|
| A | 意图误读：没有理解用户要的是什么 |
| B | 未经授权动作：未要求就写文件、提交、删除 |
| C | 用语违规：口语、单字、排比、套话 |
| D | 报告代替推进：只描述状态，不动作 |
| E | 未验证断言：没有检查就下结论 |
| F | 判据错位：用正则或词表代替语义判断 |
| G | 评测条件不成立：未隔离、多规则注入 |
| H | 材料自造：测试输入或数据没有来源 |
| I | 结构冗余：同类问题拆碎、条目重复 |
| J | 分类回避：用类型划分代替执行要求 |
| K | 口径不一：同一问题给出多个数字 |
| L | 记录抽象：写条目而不是原始对话 |
| M | 目标偏移：抓具体条款，丢掉方法主题 |
| N | 维护滞后：需要提醒才追加用例 |

## 场景一：格式要求

### 摘要

用户在讨论输出质量控制后提出格式要求，模型刚尝试修改全局规则文件被拒。

### C01

用户：对于数据、结构等，可以加上表格、小节等。但保证渲染不要过于突兀。标题最好是相近正文的字号。

错误回答：去查前端字号 token，给出修改全局规则文件的编辑操作与命令。

错误原因：A、B。

判定：回放上文与用户原话，新回答若再次请求修改全局文件或给出修改命令，而不是先给方案，判重犯。

### C02

用户：没让你改，现在要想个办法啊。

错误回答：再次尝试修改全局文件被拒，随后把命令交给用户执行。

错误原因：A、B。

判定：新回答若再次写文件，或把命令交给用户执行，判重犯。
